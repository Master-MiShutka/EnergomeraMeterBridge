# Energomera Meter Bridge

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Home Assistant App](https://img.shields.io/badge/Home%20Assistant-App-41BDF5.svg)](https://www.home-assistant.io/)
[![Version](https://img.shields.io/badge/version-1.1.1-blue.svg)](config.yaml)

Приложение (add-on) для Home Assistant, которое опрашивает электросчётчик
**Энергомера CE301(BY)** и **CE303** через TCP-шлюз (протокол IEC 61107 /
ГОСТ Р МЭК 61107-2001, режим C) и публикует показания в MQTT с автоматическим
созданием сущностей (MQTT AutoDiscovery).

> **Пароль администратора счётчика не нужен.** Приложение только читает данные, а
> все используемые параметры доступны на пользовательском уровне (таблица А.3
> инструкции). Подробнее — в разделе
> [«Нужен ли пароль администратора»](DOCS.md#нужен-ли-пароль-администратора).

## Возможности

- **Мгновенные величины** — активная мощность, напряжение и ток по фазам A/B/C.
- **Накопленная энергия** — суммарно и по тарифам T1–T5.
- **Архивы** — энергия на конец месяца, расход за последние сутки, месячные максимумы мощности по тарифам T1–T5.
- **Три режима чтения** — `array` (счётчик сам отдаёт весь массив параметров), `session` (сессия в режиме программирования) и `fast` (быстрое выборочное чтение вне сеанса).
- **Работа с «молчащими» счётчиками** — если прошивка игнорирует быстрое выборочное чтение (так ведёт себя CE301 v11 через TCP-шлюз), режим `array` открывает сеанс в режиме чтения и разбирает массив, который счётчик отдаёт сам. Массив читается только до последнего нужного параметра: цикл занимает ≈21 с вместо ≈42 с.
- **MQTT AutoDiscovery** — сущности создаются в Home Assistant автоматически, без правки `configuration.yaml`.
- **Достоверный статус связи** — сущности становятся «недоступными», если приложение потеряло брокер или счётчик (`availability_topic`).
- **Гибкая настройка** — два интервала опроса (для `fast`/`session`) и флаги `read_*`, отключающие ненужные группы параметров.
- **Устойчивый старт** — если MQTT-брокер ещё не поднялся, приложение ждёт его, а не падает; конфигурации discovery публикуются заново при каждом переподключении.
- **Диагностика связи** — опция `log_level: debug` показывает кадры обмена в HEX и тайминги, режим `--probe` перебирает варианты кадров (адресный/безадресный, 7E1/8N1) и подсказывает, что не так со шлюзом, а `--dump-array` показывает порядок параметров в массиве общего чтения.
- **Свой профиль AppArmor** — контейнер работает под профилем приложения, а не под `docker-default`: рейтинг безопасности 5 из 6.
- **Сведения об устройстве** — в режиме `array` аддон читает с счётчика заводской номер (`SNUMB`), сетевой адрес и модель: номер появляется в карточке устройства («Серийный номер») и в диагностическом сенсоре.

## Требования

| Компонент | Требование |
| --- | --- |
| Home Assistant | Home Assistant OS или Supervised (нужен Supervisor) |
| Архитектура | `aarch64`, `amd64` |
| Счётчик | Энергомера CE301(BY) с интерфейсом IEC 61107; с CE303 набор параметров совпадает, совместимость проверена частично |
| Шлюз | TCP-шлюз или конвертер «последовательный порт → Ethernet», доступный по сети |
| Брокер | MQTT-брокер, например официальное приложение **Mosquitto broker** |

## Установка

1. В Home Assistant откройте **Настройки → Дополнения → Магазин**.
2. Нажмите **⋮** (в правом верхнем углу) → **Репозитории**.
3. Вставьте адрес репозитория и нажмите **Добавить**:

   ```text
   https://github.com/Master-MiShutka/EnergomeraMeterBridge
   ```

4. Обновите страницу магазина, найдите **Energomera Meter Bridge** и нажмите **Установить**.
   Образ скачивается готовым (multi-arch, `amd64` и `aarch64`) — сборка на
   устройстве не выполняется.
5. Перейдите на вкладку **Настройки**, заполните параметры (см. ниже) и нажмите **Запустить**.

## Быстрый старт

Минимально нужно указать адрес шлюза счётчика и реквизиты MQTT-брокера:

```yaml
meter_host: "192.168.10.250"   # IP TCP-шлюза, подключённого к счётчику
meter_port: 1111               # TCP-порт шлюза
meter_address: "777777"        # сетевой адрес (IDPAS) счётчика
read_mode: "array"             # режим, который работает на CE301 v11
poll_interval: 120             # один цикл чтения ≈21 с, чаще не нужно
poll_timeout: 90               # должен покрывать вычитку массива

mqtt_host: "localhost"         # адрес MQTT-брокера
mqtt_port: 1883                # порт MQTT-брокера
mqtt_user: "mqtt_user"
mqtt_password: "mqtt_password"

topic_prefix: "main_home_meter"
```

Если счётчик отвечает на быстрое выборочное чтение, можно использовать
`read_mode: "fast"` с `poll_interval: 60` и `poll_timeout: 15` — это легче для
счётчика. Проверить, какой режим работает, помогает `python3 meter_bridge.py
--probe` (см. [«Диагностика»](DOCS.md#диагностика-и-частые-проблемы)).

Пароль счётчика (`meter_password`) для чтения не требуется — он нужен только в
режиме `read_mode: session`. Все параметры, интервалы опроса и описание устройства
описаны в **[DOCS.md](DOCS.md)**.

## Создаваемые сущности

| Сущность | Топик | Единица |
| --- | --- | --- |
| Active energy (всего, T1–T5) | `{topic_prefix}/et0pe/{total,t1,t2,t3,t4,t5}` | kWh |
| Active power | `{topic_prefix}/powep` | W |
| Voltage A / B / C | `{topic_prefix}/volta/{a,b,c}` | V |
| Current A / B / C | `{topic_prefix}/curre/{a,b,c}` | A |
| Energy at month start (всего, T1–T5) | `{topic_prefix}/enmpe/{total,t1,t2,t3,t4,t5}` | kWh |
| Energy at previous month start (всего, T1–T5) | `{topic_prefix}/enmpe_prev/{total,t1,t2,t3,t4,t5}` | kWh |
| Расход за сутки (всего, T1–T5) | `{topic_prefix}/eadpe_d0…d6/{total,t1,t2,t3,t4,t5}` | kWh |
| Maximum power (T1–T5) | `{topic_prefix}/maxpe/{t1,t2,t3,t4,t5}` | W |
| Serial number (диагностика, режим `array`) | `{topic_prefix}/serial` | — |

В режиме `fast` мгновенные величины и энергия читаются каждый «быстрый» цикл
(по умолчанию раз в 60 с), архивы — раз в «медленный» (по умолчанию раз в час).
В режиме `array` все параметры приходят за одно чтение массива.

В режиме `read_mode: array` суточный архив не публикуется: порядок его записей в
кольцевом буфере счётчика по данным не восстанавливается. Суточное потребление
считайте в Home Assistant из накопленной энергии (`utility_meter` или статистика) —
подробнее в [DOCS.md](DOCS.md#режим-array-массив-общего-чтения).

Дополнительно публикуется состояние соединения в `{topic_prefix}/status`
(`online` / `offline`, retained). Этот же топик объявлен в discovery как
`availability_topic`, поэтому при потере связи сущности переходят в статус
«недоступно».
